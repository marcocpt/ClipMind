# F1.14 用户自定义标签设计文档审核重写

> 最后更新：2026-07-29 | 版本：v1.3

## 改了什么

- 将 Design 从 v1.0 完整重写为 v2.0，基线更新为已确认的 Requirements v1.2。
- 按 Design 层级重组为 10 个标准章节，建立 8 个业务模块、3 个状态模型和 9 项关键设计决策。
- 删除具体项目目录、类或接口式模块名、数据库表、查询语句、迁移标记、缓存、事务和具体系统组件等 Implementation 细节。
- 把标签规则集中到单一协调边界，三个条目入口和设置页不再各自实现上限、重名、来源或权限规则。
- 增加自动分类标签的显式处置状态，使用户移除结果优先于重启、刷新、分类和迁移。
- 将从条目入口创建标签与关联当前条目定义为一个不可部分成功的业务操作。
- 建立统一组合筛选职责，使历史列表与搜索结果使用相同的搜索、来源和标签交集语义。
- 明确名称、颜色、来源和关联整体进入加密边界，诊断边界只接收非敏感结果元数据。
- 覆盖全部 15 条 FR、7 条 NFR 和业务约束，不再沿用 v1.0 的 13 条旧 FR 映射。
- 根据独立审查新增“新条目标签接入”，闭合分类结果、默认系统标签关联、完整持久化结果与界面发布的数据流。
- 补齐 macOS 13.0+、双处理器架构、老用户迁移、现有标签显示兼容和 App Store 主方案合规的责任映射。
- Retry 1 的 Review A、B、C 均通过；新增独立审查结果文档，记录修订轨迹、验证证据和待确认 Gate。
- 用户确认 Design v2.1 内容；仅更新 Gate 元数据为 Design v2.2，架构语义不变，工作流可进入 Visual Prototype。

## 为什么修改

- v1.0 基于未确认的 Requirements v1.0，已与用户确认的系统标签管理边界、失败回滚、安全验收和 NFR 覆盖不一致。
- v1.0 把存储表、查询语句、缓存策略、事务和迁移标记等 HOW 写进 Design，违反“职责与边界而非实现方案”的文档层级。
- v1.0 允许自动分类标签与用户标签统一全局操作，与“设置页中的自动分类标签只读”冲突。
- v1.0 把自动标签重新关联、色板数量、名称长度等已决或下游问题继续列为实现阶段待确认项，无法作为稳定架构合同。
- 现有生产架构已经存在共享条目呈现、内容分类、加密持久化、搜索与来源筛选、设置容器等接入边界，Design 应在这些职责之上定义 F1.14，而不是提前决定具体代码结构。

## 关键设计结论

- 自动分类标签与用户标签共用目录、呈现和筛选语义，但来源资格和全局管理权限由统一规则边界裁决。
- 每条目对自身自动分类标签的移除与恢复作为持久化领域事实。
- 标签区域事件由共享呈现边界消费，不传播为条目选择、详情打开或粘贴。
- 搜索、来源和全部选中标签由一个组合筛选职责解释。
- 迁移使用固定系统标签映射，且不得覆盖用户已经持久化的处置结果。
- 三个入口统一使用自动标签优先、用户标签稳定关联顺序的呈现规则。

## 影响范围

- 直接替换 F1.14 Design v1.0 草稿。
- Visual Prototype 与 Test Matrix 仍基于未确认的旧文档，继续标记为 stale；必须等待 Design 审查和用户确认后再依次同步。
- 不修改生产代码、测试代码或 F1.13 来源筛选实现。
- F1.13 当前编译缺口继续作为 Implementation 前置 blocker，不阻止 Design 审查。

## 验证

- Design 包含 10 个标准章节、8 个职责模块、15 条 FR 映射和 7 条 NFR 责任映射。
- 全文扫描未发现类名、协议名、方法调用、字段类型、实现语言、框架类型、文件扩展名或内联代码符号。
- Mermaid 图中未出现中文标点，状态名使用中文业务术语。
- Markdown 无尾随空白。
