# 主窗口最小宽度调整 history

> 日期：2026-07-27 | 功能：F1.15 主窗口最小宽度由 980 调整为 670

## 变更摘要

修复"主窗口最小宽度 980 过宽，影响小屏使用体验"问题。F1.12/F1.14 已将 `mainWindowMinWidth` 与 `appWindowMinWidth` 统一为 980 以解决嵌套冲突，但 980 对 13 寸 MacBook 等小屏设备过宽，用户难以同时容纳其他应用窗口。本次调整为 670，保证侧边栏 350 + 详情面板 320（≥ DetailPanel.minWidth=200）仍可正常显示。

## 根因

`LayoutConstants.swift` 中：

```swift
static let mainWindowMinWidth: CGFloat = 980
static let appWindowMinWidth: CGFloat = 980
```

980 来源于 F1.12 修复窗口缩放侧边栏溢出时的取值，但该值过大：

- 13 寸 MacBook（1280x800 分辨率）下 980 占屏宽 76.6%，难以容纳其他应用
- 实际侧边栏 350 + 详情面板最小 200 = 550 已足够，980 留白过多
- 用户反馈希望窗口能缩到更窄

## 修复方案

1. `LayoutConstants.mainWindowMinWidth` 由 980 调整为 670
2. `LayoutConstants.appWindowMinWidth` 同步由 980 调整为 670，保持外层与内层一致避免嵌套冲突（F1.14 修复要点）
3. 侧边栏占比约束由 50% 放宽到 60%：mainWindowMinWidth=670 后，侧边栏 350 占比 52.2% > 50%，需放宽约束；详情面板剩 320 ≥ DetailPanel.minWidth=200，仍有合理空间
4. 新增 XCTest 不变量测试 `testMainWindowMinWidthIs670` 与 `testAppWindowMinWidthIs670` 防止回归
