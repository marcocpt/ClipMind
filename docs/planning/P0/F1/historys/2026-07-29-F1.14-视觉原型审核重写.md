# F1.14 用户自定义标签视觉原型审核重写

> 最后更新：2026-07-29 | 版本：v1.2

## 改了什么

- 将视觉原型从 v1.0 完整重写为 v2.0，基线更新为已确认的 Requirements v1.2 与 Design v2.2。
- 将三个真实条目入口并列呈现，增加标签区域与条目原动作的事件隔离演示和可观察事件日志。
- 将标签菜单拆分为浏览与多选、系统标签已移除、搜索与创建、5 个上限与恢复、持久化失败回滚五种状态。
- 明确当前条目只能恢复自身自动分类标签，其他系统标签不会成为候选项。
- 补充 11 种具名预设颜色、创建后颜色不可修改、名称冲突和标签上限反馈。
- 增加搜索、来源、多个标签交集组合及独立的“筛选无结果”空状态。
- 将设置页中的系统标签调整为全局只读，仅向用户自定义标签提供重命名和删除操作。
- 增加确认对话框、大小写不敏感的重名校验、持久化失败回滚和安全错误文案。
- 增加迁移进行、可恢复中断、无重复、用户移除优先、新条目完整发布和半完成条目不发布状态。
- 增加键盘焦点、来源与状态文本、颜色名称、空状态区分和跨入口一致性的可访问性说明。
- 修正嵌套按钮结构，将条目原动作与标签触发拆分为兄弟按钮，并保留原生键盘激活。
- 根据独立审查 Retry 1 将原型升级为 v2.1：同一条目和无标签条目均在三个入口并列展示，标签菜单按条目上下文生成候选与勾选状态。
- 增加轻量交互状态模型，使搜索、即时勾选或取消、系统标签恢复、创建并关联、上限释放、失败重试、筛选清除、重命名与删除均产生可见状态变化。
- 并列展示历史列表与搜索结果的同一条目标识，并分别呈现“无剪贴历史”和“筛选无结果”两种空状态。
- 将条目原动作与标签按钮改为兄弟控件，菜单项使用可聚焦 checkbox 角色和显式状态，确认对话框增加名称、焦点进入、焦点循环、Escape 或取消返回合同。
- 增加不新增权限或 entitlement 的发布边界说明，并使迁移期间条目保持可操作。
- 根据 Retry 1 复审将原型升级为 v2.2：系统标签恢复复用统一 5 标签上限裁决，不再存在第 6 个标签路径。
- 让主窗口筛选“+”打开可操作多选区域，标签选择会实时更新交集结果或筛选空状态。
- 历史列表、搜索结果和筛选条件改为消费共享标签状态，全局重命名或删除会同步刷新全部可见消费者。
- 将重命名拆分为“编辑并提交新名称”与“显示旧名、新名并确认”两个阶段，取消时保持原名称。
- 将错误回滚和已移除状态中的纯展示 checkbox 设为显式禁用；失败重试目标随当前标签目录动态生成。
- 初始化所有场景切换按钮的 `aria-pressed`，并在确认 modal 打开时隔离背景指针和焦点交互。

## 为什么修改

- v1.0 允许在设置页重命名或删除系统标签，与用户确认的 F1.14-D01 和 FR-012 冲突。
- v1.0 在条目候选菜单中暴露非当前分类结果对应的系统标签，与 FR-008 的恢复资格边界冲突。
- v1.0 未覆盖三个入口的点击隔离、5 个上限、筛选无结果、失败回滚、迁移可用和完整发布等已确认状态。
- Design Gate 已关闭，视觉原型需要把确认后的职责、状态和失败边界转化为可检查的 UI 合同。

## 影响范围

- 直接替换 F1.14 视觉原型 v1.0 草稿。
- 不修改 Requirements、Design、生产代码或测试代码。
- 测试用例表继续保持 stale，必须等待视觉原型审查和用户确认后再同步。
- F1.13 当前编译缺口仍是 Implementation 前置 blocker，不影响本次视觉文档审核。

## 验证

- HTML 结构解析通过，不存在未闭合标签或嵌套按钮。
- 使用本机 Chrome 在 1440 × 1000 视口渲染 6 个主场景和 5 个菜单状态，未发现溢出、遮挡或不可读状态。
- 自动化交互回归覆盖三入口双状态、键盘事件隔离、上下文候选、搜索创建、名称校验、系统标签恢复与上限、筛选新增与交集变化、两阶段重命名、全局传播、失败重试、双空状态、modal 隔离与焦点、迁移可用。
- DOM 语义检查确认不存在嵌套交互控件，页面脚本与浏览器控制台无错误。
- 浏览器控制台与页面脚本无错误，所有主场景和菜单状态均能唯一激活。
