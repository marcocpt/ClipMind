# F1.11 全局热键面板跟随外置显示器就近出现

> 最后更新：2026-07-26 | 版本：v1.0

## 变更摘要

本次提交修复 F1.11 全局快捷键呼出快速粘贴面板的 Bug：当用户在外置显示器（副屏）的输入框中按全局快捷键时，面板没有跟随 caret 就近出现在副屏，而是被强制拉回主屏边界，导致「就近出现」体验失效。

修复方案：`CaretPanelLocator` 新增 `screenFinder` 闭包，钳制时按 caret/鼠标坐标查找所在屏幕的 frame，确保面板留在锚点所在屏内；`AccessibilityService` 的 Y 坐标翻转从 `NSScreen.main` 改为 `NSScreen.screens.first`（主屏），避免 AXUIElement/CGEvent 全局坐标系被副屏高度错误翻转。

## 根因分析

### 1. CaretPanelLocator 钳制使用主屏 frame

`CaretPanelLocator.locatePosition(lastClosedPosition:)` 在有权限路径下计算面板期望位置后，调用 `clampToScreen(position:panelSize:screenFrame:)` 做边界钳制。原实现中 `screenFrame` 来自 `screenFrameProvider()`（默认 `NSScreen.main?.frame`），即主屏 frame。

当 caret 在副屏（例如主屏 1512×944 右侧接副屏 1920×1080）时，caret 坐标例如 (2000, 500)，面板期望位置 X=2050，但被主屏 frame 钳制为 X=1512-panelSize.width≈1112，强制把面板从副屏拉回主屏右边缘。

### 2. AccessibilityService Y 坐标翻转用 NSScreen.main 高度

`AccessibilityService.locateCaretViaAccessibilityAPI()` 与 `locateMouseViaCGEvent()` 把 AXUIElement/CGEvent 的全局坐标（左上角原点，Y 向下）翻转为 Cocoa 坐标（左下角原点，Y 向上）：

```swift
let screenHeight = NSScreen.main?.frame.height ?? 0
return NSPoint(x: ..., y: screenHeight - globalY)
```

macOS 全局坐标系原点是主屏（`NSScreen.screens[0]`）左上角，整个坐标空间用主屏高度做翻转。但 `NSScreen.main` 是「当前键盘焦点所在屏」，副屏输入时会变成副屏 frame，导致 Y 翻转用了副屏高度（例如 1080）而非主屏高度（944），caret Y 坐标计算错误。

## 关键设计决策

### 1. screenFinder 闭包按锚点找所在屏

新增 `screenFinder: (NSPoint) -> NSRect` 闭包（默认 `NSScreen.screens.first { $0.frame.contains(point) }?.frame ?? NSScreen.main?.frame ?? .zero`）。`clampToScreen` 接收 `anchor: NSPoint`（caret 或鼠标位置），通过 `screenFinder(anchor)` 找到锚点所在屏的 frame，再钳制到该屏可视范围。

为什么用锚点而不是面板期望位置：面板期望位置可能因为 caret 偏移量（50px）落在两屏边界外（例如 caret 在副屏左边缘，面板 X = caret.x + 50 可能还在副屏内但接近边界）。用锚点（caret/鼠标真实位置）找所在屏更稳定，避免边界震荡。

### 2. NSScreen.screens.first 而非 NSScreen.main

`NSScreen.main` 是「当前键盘焦点所在屏」，副屏输入时会变成副屏；`NSScreen.screens.first`（即 `screens[0]`）始终是系统设置中标注为主显示器的那块屏。macOS 全局坐标系（AXUIElement 与 CGEvent 共用）原点固定在主屏左上角，Y 向下增加，整个坐标空间用主屏高度做翻转。所以 Y 翻转必须用 `screens.first?.frame.height`，否则副屏输入时翻转基准错误。

### 3. 测试类标 @MainActor

`PanelScreenLocating` 协议标 `@MainActor`，新增 `screenFinder` 默认闭包引用 `NSScreen.screens`（main actor-isolated 静态属性），导致 `CaretPanelLocator.init` 也成为 main actor-isolated。测试类需要 `@MainActor` 注解才能在主线程上下文调用 init 与 `locatePosition`。

原有 5 条测试不受影响，仍能通过；新增 2 条多屏测试覆盖副屏 caret/鼠标场景。

### 4. screenFinder 默认值回退到 NSScreen.main

`screenFinder` 默认闭包找不到锚点所在屏时回退到 `NSScreen.main?.frame ?? .zero`。这是兜底：理论上锚点坐标总能在 `NSScreen.screens` 中找到所在屏，但极端情况（坐标在屏间隙、屏掉线等）下回退到主屏比 `.zero` 更合理。

## 影响的 AC

- **AC-F1.9-2**（面板在 caret 附近显示）：修复后，caret 在副屏时面板跟随出现在副屏 caret 附近，不再被强制拉回主屏。
- **AC-F1.9-3**（无 caret 时面板在鼠标位置附近）：修复后，鼠标在副屏时面板跟随出现在副屏鼠标位置附近。
- **AC-F1.9-12**（多屏支持）：原决策「首版仅主屏」被推翻，现支持多屏就近定位。
