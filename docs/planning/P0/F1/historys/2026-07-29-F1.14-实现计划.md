# F1.14 用户自定义标签实现计划

> 最后更新：2026-07-29 | 版本：v1.0

## 改了什么

- 新增 F1.14 Implementation Plan 主索引、Phase 0～6 子计划和 check-plan 审核摘要。
- 将已确认的 Requirements v1.2、Design v2.2、Visual Prototype v2.3、Test Matrix v2.3 转化为 7 个顺序 Phase。
- 建立统一标签领域、加密目录/关联事务、可恢复迁移、三个入口共享 picker、组合筛选、设置管理、UI 证据和发布合规路径。
- 明确 `EncryptedStore.update(_:)` 必须保留最新 `tagState`，避免内容编辑或 LLM 结果用旧快照覆盖标签。
- 将 `TagStore` 拆为独立 load generation、FIFO mutation queue 和 migration task。
- 为三入口 UI 建立从 Phase 2 开始、随 Phase 3/4/5 增长的 exact-SHA UI Smoke。
- 固定受控真实粘贴 positive control、失败注入、性能、稳定性、辅助功能和 Release 排除证据。
- 为 App Sandbox 增加官方 container migration manifest 方案和 disposable upgrade-seed 验证。
- 将兼容证据拆为 macOS 15 原生 arm64/x86_64 CI 与 macOS 13 主 Release/ReleaseDev 双 lane。
- 明确 Implementation integration 与 Final Candidate 的边界，后者必须基于最新 `develop` 重跑完整证据。

## 为什么修改

- 规格套件已经确认，需要一份可直接按 TDD 执行、可恢复、可独立回滚的实施顺序。
- F1.13 当前编译缺口会让 F1.14 组合筛选失去可信基线，必须在 Phase 0 显式阻断。
- 现有 `content_blob` 整体更新、非隔离异步任务、无 Sandbox 旧库迁移和 arm64-only CI 都可能造成数据或验收误判。
- UI 行为必须通过真实控件、resultId、receiver text、paste count、Release artifact 和 exact SHA 证明。

## 影响范围

- 新增 `docs/planning/P0/F1/plans/F1.14-用户自定义标签/` 下的计划与审核文档。
- 不修改 Requirements、Design、Visual Prototype 或 Test Matrix 的已确认语义。
- 不修改生产代码、测试代码、CI、entitlement、`project.yml` 或生成工程。
- Planning 完成后只允许进入 Implementation Phase 0；不能越过 F1.13 blocker。

## 独立审查

- 审查等级：Standard，1 名独立 reviewer，按 A 覆盖、B 正确性、C 可验证性三视角。
- 初审发现 10 类 Must-fix；Retry 1/2 继续关闭升级 seed、Release/Dev 证据边界、工程生成和新 workflow exact-SHA 触发问题。
- Retry 3 最终 A/B/C 全部 PASS，0 Must-fix。
- 详细轨迹见 `plans/F1.14-用户自定义标签/check-plan-审核摘要.md`。

## 验证

- 8 份计划文档的元数据、版本记录和相对链接通过检查。
- README 中 AC-1～24 映射完整。
- 无 TODO、TBD、未决实现占位符或已知未定义符号。
- 文档 whitespace check 无输出。
- 最终 reviewer 结论：A PASS、B PASS、C PASS。

## 后续 Gate

- 当前立即 blocker：F1.13 来源筛选基线缺少实现符号且 build exit 65。
- 后期基础设施 blocker：当前无受控 macOS 13 runtime runner/设备证据。
- Sandbox 关闭与 arm64-only CI 是 Phase 6 要关闭的实现项，不是 Planning blocker。
