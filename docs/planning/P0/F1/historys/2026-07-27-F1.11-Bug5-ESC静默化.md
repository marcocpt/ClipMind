# F1.11 Bug 5 ESC 关闭弹窗静默化

> 最后更新：2026-07-27 | 版本：v1.0

## 变更摘要

本次提交修复 F1.11 菜单栏弹窗双击粘贴功能的 Bug 5：按 ESC 关闭菜单栏弹窗（NSPopover）时，macOS 会播放系统默认提示音（咚/错误音），破坏「快速复用」的体验。

修复方案：新增 `PanelKeyEventHandler` 模块在 `NSEvent.addLocalMonitorForEvents` 监听器中消费 ESC 事件（返回 nil），阻止事件传播到 `NSResponder.cancelOperation` 默认实现调用 `NSBeep()`。其他键（Enter/方向键/未处理键）原样返回，保留 TextField 编辑能力。

## 关键设计决策

### 1. 仅消费 ESC 事件

`PanelKeyEventHandler.handle(_:)` 仅对 ESC（keyCode 53）返回 nil 消费事件，其他键（Enter/Up/Down/未处理键）原样返回。

原因：`NSBeep()` 仅由 ESC 触发（`NSResponder` 默认 `cancelOperation` 调用 `NSBeep`）；其他键传播不会产生提示音，且 TextField 需要这些键正常工作（光标移动、文本输入）。

### 2. 抽取独立 PanelKeyEventHandler 模块

原 `UnifiedPastePanelView.startKeyMonitor` 内联 `handleKeyEvent` 方法处理键盘事件。Bug 5 抽取为独立的 `PanelKeyEventHandler` 结构体。

原因：
- 便于单元测试（XCTest 直接构造 `NSEvent` 验证路由逻辑，无需启动 GUI）
- 职责单一（仅处理键盘事件路由，不持有状态）
- 与 `viewModel.handleEscKey()` / `viewModel.handleEnterKey()` 等回调解耦

### 3. 测试策略：XCTest + 手动验证

- **XCTest 部分**：`test_handle_escKey_returnsNilToConsumeEvent` 验证 ESC 事件被消费（返回 nil），通过 `XCTAssertNil(result)` 断言
- **手动验证部分**：用户在实机确认按 ESC 关闭弹窗无提示音（系统音频无法在 CI 自动化验证）

## 根因分析

### 问题现象

按 ESC 关闭菜单栏弹窗时，macOS 播放系统默认提示音（咚/错误音）。

### 根本原因

macOS 的 `NSResponder` 链对 ESC 键有默认实现 `cancelOperation(_:)`，该默认实现会调用 `NSBeep()` 播放系统提示音。

`NSEvent.addLocalMonitorForEvents(matching: .keyDown)` 监听器原实现返回 ESC 事件（非 nil），事件继续传播到 `NSResponder` 链，触发 `cancelOperation` 默认实现 → `NSBeep()`。

### 修复方案

在事件监听器中对 ESC 事件返回 nil，消费事件阻止传播到 `NSResponder` 链。`viewModel.handleEscKey()` 仍被调用执行关闭弹窗逻辑，但 `NSBeep` 不再触发。

## 影响的 AC

- **AC-F1.11-5**（Esc 键关闭菜单栏弹窗）：Bug 5 修复后，按 ESC 关闭弹窗时静默无提示音，与用户对「快速关闭」的预期一致。原 AC 行为（关闭弹窗 + 不粘贴）保持不变，仅消除提示音副作用。
