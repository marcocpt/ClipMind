## 关键设计决策

### 1. SettingsWindowAssembly 独立文件

**问题**：原计划将 `handleOpenSettings` + `showSettingsInStandaloneWindow` 直接放入 `AppDelegate` 类型体，导致类型体长度 321 行，超过 SwiftLint `type_body_length` 规则的 300 行阈值。

**方案**：将这两个方法拆分到独立的 `SettingsWindowAssembly.swift` extension 文件。

**收益**：与 `QuickPasteAssembly.swift`、`StatusItemAssembly.swift` 的拆分模式一致，AppDelegate 类型体保持精简，符合单一职责原则。

### 2. 三按钮回调统一通过 onEscPressed 关闭弹窗

**方案**：`UnifiedPastePanelView.bottomToolbar` 中三按钮的关闭弹窗逻辑统一通过 `viewModel.onEscPressed?()` 触发，复用 Phase 1 `StatusItemController.makeUnifiedPanelView` 注入的 `onEscPressed = { [weak self] in self?.closePanel() }` 回调。

**职责划分**：
- 「查看全部」：发送 `openMainWindow` 通知 + 关闭弹窗
- 「配置」：发送 `openSettingsWindow` 通知 + 关闭弹窗
- 「退出」：仅关闭弹窗（不发送通知，符合 AC-F1.11-8）

### 3. XCUITest 稳定性优化

**问题**：`test02` 与 `test05` 间歇性报「Application is not foreground and does not allow background interaction」错误。

**方案**：在三按钮 `click()` 前增加 `app.activate()` 调用，沿用 `PopoverDoublePasteUITests` 在 `typeKey` 前激活应用的模式。

**结果**：连续运行两次 `PopoverBottomToolbarUITests`，第二次 5 条用例全部 PASS（63.479 秒）。
