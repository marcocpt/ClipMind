## 关键设计决策

### 1. SettingsWindowAssembly 独立文件

**问题**：原计划将 `handleOpenSettings` + `showSettingsInStandaloneWindow` 直接放入 `AppDelegate` 类型体，导致类型体长度 321 行，超过 SwiftLint `type_body_length` 规则的 300 行阈值。

**方案**：将这两个方法拆分到独立的 `SettingsWindowAssembly.swift` extension 文件。

**收益**：与 `QuickPasteAssembly.swift`、`StatusItemAssembly.swift` 的拆分模式一致，AppDelegate 类型体保持精简，符合单一职责原则。

### 2. 三按钮回调统一通过 onEscPressed 关闭弹窗

**方案**：`UnifiedPastePanelView.bottomToolbar` 中三按钮的关闭弹窗逻辑统一通过 `viewModel.onEscPressed?()` 触发，复用 Phase 1 `StatusItemController.makeUnifiedPanelView` 注入的 `onEscPressed = { [weak self] in self?.closePanel() }` 回调。

**职责划分**：
- 「查看全部」：发送 `openMainWindow` 通知 + 关闭弹窗
- 「配置」：发送 `openSettingsWindow` 通知 + 关闭弹窗
- 「退出」：仅关闭弹窗（不发送通知，符合 AC-F1.11-8）

### 3. XCUITest 稳定性优化

**问题**：`test02` 与 `test05` 间歇性报「Application is not foreground and does not allow background interaction」错误。

**方案**：在三按钮 `click()` 前增加 `app.activate()` 调用，沿用 `PopoverDoublePasteUITests` 在 `typeKey` 前激活应用的模式。

**结果**：连续运行两次 `PopoverBottomToolbarUITests`，第二次 5 条用例全部 PASS（63.479 秒）。

### Flaky Test 记录

**现象**：`test02`（查看全部）与 `test04`（退出）在套件首跑时偶发失败，报错 `XCTAssertFalse failed - 搜索框应不存在`，但单独运行与套件重跑均通过。

**根因**：`PopoverPreviewWindowFactory` 中注册的 `NSWindow.didBecomeKeyNotification` 监听器与 `viewModel.onEscPressed?()` → `window.close()` 存在时序竞争。`onViewAll` 同步发送 `openMainWindow` 通知触发主窗口成为 key，监听器 `orderOut` 主窗口并让 popover 重新成为 key，与随后的 `close()` 产生竞争，导致 accessibility 元素在 2 秒 timeout 内未清理。

**影响范围**：仅影响 UITEST 模式下的测试稳定性，不影响生产环境功能正确性（生产环境 `StatusItemController` 直接调用 `closePanel()`，无 `didBecomeKeyNotification` 监听器）。

**后续优化方向**（不在 Phase 3 范围内）：
1. 在 `PopoverPreviewWindowFactory` 的 `didBecomeKeyNotification` 监听器中，当 popover 已 `close` 后立即移除监听器
2. 或在 `onEscPressed` 回调中先移除监听器再 `close`
3. 或增加 `waitForNonExistence` 的 timeout 到 3 秒

## Flaky Test 修复（v1.2 补充）

**修复时间**：2026-07-25 18:42 ~ 18:47

### 修复内容

1. **`PopoverPreviewWindowFactory.swift`**：新增 `NSWindow.willCloseNotification` 监听器，保存 `didBecomeKeyNotification` 监听器 token，在 popover 窗口关闭时移除监听器，避免 close 后延迟触发的 didBecomeKey 事件导致主窗口被误 orderOut。

2. **`UnifiedPastePanelView.swift`**：调整 `onViewAll`/`onSettings` 回调顺序为「先 `onEscPressed`（close）后发送通知」，确保 close 触发 willClose 清理监听器后再让主窗口/设置窗口成为 key。
