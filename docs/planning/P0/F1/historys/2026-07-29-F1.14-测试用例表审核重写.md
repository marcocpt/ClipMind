# F1.14 用户自定义标签测试用例表审核重写

> 最后更新：2026-07-29 | 版本：v1.1

## 改了什么

- 将 Test Matrix 从基于未确认 v1.0 上游文档的草稿完整重写为 v2.0。
- 基线更新为已确认的 Requirements v1.2、Design v2.2 与 Visual Prototype v2.3。
- 采用用户确认的 AC 中心方案，建立 24 条 AC 的 FR/NFR、详细用例与覆盖状态追踪。
- 将复杂 AC 拆分为三个入口、成功、取消、失败、回滚、重启恢复、迁移、性能、辅助功能和合规等原子路径。
- 每条详细用例补齐 Given、When、Then、测试层级、自动或手动方式、可观察证据与风险依赖。
- 对照实际代码和测试后，将既有系统标签显示、搜索/来源筛选、剪贴项加密和非标签日志脱敏标为 PARTIAL；F1.14 新能力保持 MISSING。
- 明确当前无 COVERED、无获批 DEFERRED，并记录 F1.13 编译缺口对完整验收的阻塞边界。
- 固定性能环境、测量方法和阈值，避免在实现阶段临时解释 NFR。
- 独立审查 Retry 1 将 PARTIAL 收敛为可按 AC 复算的具体测试方法或项目文件证据，消除跨 AC 模糊映射。
- Retry 1 为菜单栏弹窗和快捷粘贴面板定义受控接收文本、粘贴计数与 positive control，设置页可见列表用于证明达到上限时没有孤立目录项。
- Retry 1 将性能拆为领域/存储、真实 UI、迁移和首个可交互界面四层，固定 20 次 nearest-rank p95；稳定性拆为自动状态验证和独立 Instruments 人工证据。

## 为什么修改

- v1.0 仅覆盖旧的 14 条 AC，无法追踪已确认 Requirements v1.2 的 24 条 AC。
- v1.0 把操作步骤拆成自然语言列，但没有标准 Given/When/Then、证据和依赖，无法直接驱动 TDD 或验收。
- v1.0 将全部用例统一标为 MISSING，没有区分可复用的旧能力与 F1.14 核心缺口。
- Visual Prototype v2.3 已确认，Test Matrix 必须把三个入口、双空态、真实五标签恢复、两阶段重命名、全部系统标签筛选和失败回滚转化为可执行证据。

## 影响范围

- 直接替换 F1.14 Test Matrix v1.0 草稿。
- 不修改 Requirements、Design、Visual Prototype、生产代码或测试代码。
- F1.13 来源筛选编译缺口继续阻止 Implementation 与完整验收，但不阻止 Test Matrix 文档审查。

## 验证

- Requirements v1.2 的 15 条 FR 与 24 条 AC 均在追踪总表中出现。
- 7 条 NFR 均通过 AC-17～24 映射到详细用例。
- 每条详细用例均包含 Given、When、Then、层级/方式、可观察证据、覆盖状态和风险依赖。
- 覆盖状态仅使用实际代码和测试证据；没有未经批准的 DEFERRED。
- 59 条详细 Case ID 唯一，全部追踪引用都能解析到详细用例；8 个 PARTIAL Case 仅聚合到 AC-10、15、18、19、23、24。
- UI 负向断言具有可读取的 `pasteReceiverText`、`pasteEventCount` 或设置页标签列表证据；性能与稳定性层级均能观察对应结果。
- Markdown 通过 `git diff --check`。
