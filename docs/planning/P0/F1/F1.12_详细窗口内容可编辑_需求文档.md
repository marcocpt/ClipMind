## 1. Background（背景）

ClipMind 已交付初赛 MVP（F1.1~F1.7）和后续增强功能（F1.8~F1.11）：

- F1.1~F1.7 完成剪贴板监听与捕获、自动分类、语义搜索、一键处理、本地加密存储、隐私保护、菜单栏常驻 + 主窗口交互。
- F1.7 主窗口详情面板（DetailPanel）当前使用只读 `Text` 视图展示剪贴项内容，用户无法在详情面板中直接编辑文本。

用户捕获的剪贴板内容有时需要微调：修正错别字、补充说明、调整格式、修改文件路径等。当前用户必须复制内容到外部编辑器修改后重新复制，操作路径冗长。

F1.12 的目标是在主窗口详情面板中增加内容编辑能力：文本类型和文件路径类型支持点击进入编辑模式、实时自动保存、Cmd+Z 撤销；图片类型显示不可编辑提示；编辑后同步内容到系统剪贴板；AI 处理按钮在编辑后仍可正常使用。

本特性沿用已有的 DetailPanel 视图和 onUpdateClip 回调机制，沿用 EncryptedStore 持久化方案（需新增 update 方法），不引入新的权限申请流程，不修改剪贴板捕获和分类逻辑。

## 2. Problem Statement（问题定义）

**核心问题**：主窗口详情面板中的剪贴项内容为只读展示，用户无法原地编辑，导致以下可验证问题：

1. **详情面板内容不可编辑**：DetailPanel 使用只读 `Text` 视图展示内容，用户无法点击进入编辑模式。可验证：点击详情面板文本区域，无光标出现，无法输入。
2. **修改剪贴内容需外部操作**：用户发现捕获的文本有错别字或需要补充说明时，必须复制内容到外部编辑器修改后重新复制，至少 4 步操作（选中 → 复制 → 切换编辑器 → 修改 → 重新复制），破坏「原地修改」的直觉操作。
3. **编辑后不同步到系统剪贴板**：即使允许编辑，编辑后的内容不会同步到系统剪贴板，用户粘贴时仍使用旧内容。可验证：假设编辑成功后，系统剪贴板仍为原始内容。
4. **图片类型无编辑提示**：图片类型内容点击后无反馈，用户不确定是功能缺失还是不支持编辑。可验证：选中图片类型条目后，详情面板无任何编辑相关提示。
5. **文件路径类型不可编辑**：文件路径内容以纯文本形式展示，用户无法直接修改路径文本。可验证：文件路径类型条目的详情面板内容与文本类型相同，但不支持编辑。

**影响用户**：所有在详情面板查看剪贴项内容的用户，尤其是开发者（修正代码片段、修改报错描述）、文案工作者（调整文本内容、补充翻译素材）、项目经理（修改需求描述、更新待办事项）。

**不解决会怎样**：详情面板仅作为「只读查看器」，用户无法在 ClipMind 内完成「查看 → 发现问题 → 修正 → 复用」的完整工作流，被迫切换到外部编辑器，降低 ClipMind 作为信息库的核心价值。

## 3. Goals（目标）

### 3.1 用户目标

- 用户在主窗口详情面板中点击文本内容区域，**直接进入编辑模式**，出现光标可输入。
- 编辑过程中**实时自动保存**到数据库，无需手动保存按钮，切换到其他剪贴项时自动保存当前编辑。
- 支持 **Cmd+Z 撤销**编辑操作，遵循 macOS 标准撤销行为。
- 编辑保存后**同步内容到系统剪贴板**（NSPasteboard.general），用户在其他应用粘贴时使用最新内容。
- 文件路径类型支持**编辑路径文本**（修改路径字符串）。
- 图片类型显示**「图片内容不支持编辑」提示**，明确告知用户不可编辑原因。
- 编辑后**AI 处理按钮仍可正常使用**，处理结果基于编辑后的最新内容。

### 3.2 业务目标

- 把详情面板从「只读查看器」升级为「可编辑查看器」，完善「查看 → 编辑 → 处理 → 复用」完整工作流。
- 实时自动保存消除用户「忘记保存」的焦虑，切换条目时自动保存保证数据不丢失。
- 编辑后同步到系统剪贴板，保证用户在其他应用粘贴时使用最新内容。
- 沿用已有的 DetailPanel 视图和 onUpdateClip 回调机制，沿用 EncryptedStore 持久化方案，不引入新的权限申请流程。

### 3.3 成功标准

- 文本类型：点击文本区域进入编辑模式 → 编辑内容实时自动保存到数据库 → 切换到其他条目时自动保存 → Cmd+Z 撤销可用。
- 文件路径类型：点击路径文本区域进入编辑模式 → 编辑路径文本实时自动保存。
- 图片类型：显示「图片内容不支持编辑」提示。
- 编辑保存后，内容同步到系统剪贴板（NSPasteboard.general）。
- 编辑后 AI 处理按钮仍可正常使用，处理结果基于编辑后的内容。
- 8 条 AC 全部通过（自动化测试 + 手动验收）。

## 5. Functional Requirements（功能需求）

### FR-001：文本类型点击进入编辑模式

**需求**：用户在详情面板中点击文本内容区域时，进入编辑模式，出现光标可输入。

**行为**：

- 详情面板展示文本类型（`.text`）条目时，默认为只读展示模式。
- 用户点击文本内容区域，切换为编辑模式：只读 `Text` 视图替换为可编辑 `TextEditor` 视图，光标出现在点击位置。
- 编辑模式下，用户可正常输入、删除、选择文本。
- 编辑模式下，详情面板其他区域（元信息、AI 处理按钮、结果展示）保持不变。

### FR-002：文本内容实时自动保存

**需求**：文本类型条目在编辑模式下，内容变化实时自动保存到数据库。

**行为**：

- 每次文本内容发生变化时，触发自动保存到数据库（EncryptedStore）。
- 自动保存采用防抖策略：内容变化后延迟指定时间（设计文档确定具体值）再保存，避免高频写入。
- 自动保存过程中不阻塞 UI 交互。
- 自动保存失败时，在详情面板显示错误提示（非阻塞），用户可继续编辑。
- 自动保存成功后，ClipStore 中的对应条目同步更新。

### FR-003：Cmd+Z 撤销编辑

**需求**：编辑模式下，用户可通过 Cmd+Z 撤销编辑操作。

**行为**：

- 编辑模式下按 Cmd+Z：撤销最近一次编辑操作（遵循 SwiftUI TextEditor 内置撤销行为）。
- 连续按 Cmd+Z：逐步撤销更早的编辑操作。
- 撤销操作触发自动保存（与手动编辑相同）。
- 撤销到初始状态后再按 Cmd+Z：不产生任何效果（已是最初状态）。

### FR-004：切换条目时自动保存

**需求**：用户在详情面板中切换到其他剪贴项时，当前编辑的条目自动保存。

**行为**：

- 用户在历史列表中点击其他条目时，当前编辑的条目先保存到数据库，再切换到新条目。
- 保存完成后，详情面板展示新选中的条目内容。
- 切换时若保存失败，显示错误提示，但仍然切换到新条目（不阻塞切换操作）。
- 切换时若当前条目内容未变化，不触发保存操作。

### FR-005：编辑后同步到系统剪贴板

**需求**：编辑内容保存到数据库后，同步更新到系统剪贴板（NSPasteboard.general）。

**行为**：

- 自动保存成功后，将编辑后的文本内容写入系统剪贴板（仅文本类型和文件路径类型）。
- 写入系统剪贴板使用 `NSPasteboard.general.clearContents()` + `setString(_:forType:)` 。
- 系统剪贴板同步失败时不阻塞编辑和自动保存，仅记录日志。
- 图片类型不触发系统剪贴板同步（图片类型不可编辑）。

### FR-006：文件路径类型可编辑

**需求**：文件路径类型（`.filePath`）条目在详情面板中支持编辑路径文本。

**行为**：

- 详情面板展示文件路径类型条目时，默认显示路径文本（多个路径以换行分隔）。
- 用户点击路径文本区域，进入编辑模式，可修改路径文本。
- 编辑行为与文本类型一致：实时自动保存、Cmd+Z 撤销、切换条目时自动保存。
- 保存后同步到系统剪贴板（写入路径文本字符串）。
- 文件路径编辑仅修改路径文本字符串，不验证路径是否存在、不修改实际文件。

### FR-007：图片类型显示不可编辑提示

**需求**：图片类型（`.image`）条目在详情面板中显示不可编辑提示。

**行为**：

- 详情面板展示图片类型条目时，在图片内容区域下方显示提示文本「图片内容不支持编辑」。
- 提示文本使用次要文字颜色，字体大小小于正文。
- 图片内容区域不支持点击进入编辑模式。
- 提示始终可见（不需要用户触发），明确告知不可编辑原因。

### FR-008：编辑后 AI 处理按钮仍可用

**需求**：编辑内容后，详情面板的 AI 处理按钮仍可正常使用，处理结果基于编辑后的最新内容。

**行为**：

- 编辑模式下或编辑完成后，AI 处理按钮（智能总结/即时翻译/智能改写/提取待办）保持可用状态。
- 点击 AI 处理按钮时，使用当前编辑后的最新内容（而非原始捕获内容）作为处理输入。
- AI 处理结果正常展示在详情面板结果区域。
- 处理按钮的可用状态（是否置灰）仍取决于 API Key 是否已配置，与编辑无关。

## 6. Non-functional Requirements（非功能需求）

### NFR-001：响应性能

- 点击文本区域到进入编辑模式（光标出现）：≤ 100ms（用户感知「瞬间切换」）。
- 内容变化到自动保存完成：≤ 500ms（防抖延迟 + 数据库写入）。
- 自动保存过程中不阻塞 UI 交互：保存操作在后台执行，UI 保持响应。
- 切换条目时自动保存延迟：≤ 200ms（不影响切换体验）。
- 系统剪贴板同步：≤ 50ms（NSPasteboard 写入为内存操作）。

### NFR-002：稳定性

- 编辑模式与只读模式切换在 100 次连续操作中无崩溃、无内存泄漏。
- 自动保存在快速连续输入（每秒 10 次内容变化）场景下不丢数据、不重复保存。
- 切换条目时自动保存与加载新条目不冲突，不出现旧内容闪现或新内容覆盖。
- 系统剪贴板同步与自动保存不冲突，不出现剪贴板内容与数据库不一致。

### NFR-003：安全性

- 不在日志中输出编辑内容原文、剪贴板原文等敏感信息。
- 自动保存的编辑内容与原始捕获内容使用相同的 AES-256-GCM 加密存储。
- 系统剪贴板同步不绕过现有的敏感识别与应用黑名单。
- 编辑内容不会导致数据库加密强度降低。

### NFR-004：兼容性

- 兼容 macOS 13.0+（与项目主设计规范一致）。
- 兼容 Apple Silicon（arm64）与 Intel（x86_64）。
- 兼容现有详情面板功能（元信息展示、AI 处理按钮、结果展示）不变。
- 兼容现有 ClipStore 和 EncryptedStore 接口（新增 update 方法，不修改现有方法签名）。
- 老用户升级无感知迁移：已有条目默认为只读模式，点击后进入编辑模式。

### NFR-005：可访问性

- 编辑模式下的 TextEditor 支持 VoiceOver 朗读。
- 编辑模式的进入和退出可通过键盘操作。
- 不可编辑提示文本支持 VoiceOver 朗读。
- Cmd+Z 撤销使用标准键盘快捷键，无需自定义快捷键。

### NFR-006：合规性（App Store）

- 主方案保持 App Store 合规：启用 App Sandbox、仅申请最小必要 entitlement、不使用私有 API。
- 系统剪贴板写入使用公开 API（NSPasteboard.general），完全合规。
- 数据库写入使用现有加密存储方案，完全合规。
- 不引入新的权限申请流程。

### NFR-007：可维护性

- 编辑逻辑封装在详情面板视图内，不扩散到其他模块。
- 自动保存逻辑封装在独立方法中，便于测试和修改。
- 新增的 EncryptedStore update 方法与现有 save 方法保持一致的加密和序列化逻辑。

## 7. Constraints（约束）

### 7.1 业务约束

- **不改剪贴板捕获逻辑**：PasteboardWatcher 的监听、去重、分类逻辑保持不变。
- **不改分类逻辑**：编辑后的内容不重新触发自动分类（分类结果保持原值）。
- **不改 AI 处理逻辑**：AI 处理（总结/翻译/改写/提取待办）的调用方式不变，仅输入内容变为编辑后的最新内容。
- **不改隐私保护逻辑**：敏感识别与应用黑名单逻辑保持不变。
- **不改菜单栏弹窗与快捷粘贴面板**：F1.9 和 F1.11 的功能保持不变。

### 7.2 兼容约束

- **macOS 13.0+**：与项目主设计规范一致。
- **老用户无感知迁移**：已有条目默认只读模式，点击进入编辑模式，无需用户配置。
- **现有测试用例回归**：F1.1~F1.11 已有的自动化测试用例必须通过。

### 7.3 合规约束

- **App Store 主方案合规**：所有面向发布的代码必须满足 App Store Review Guidelines 与 macOS 沙盒、隐私、权限约束。
- **加密存储一致性**：编辑内容使用与原始内容相同的 AES-256-GCM 加密存储方案。

## 8. Acceptance Criteria（验收标准）

> **格式约定**：每条 AC 用 Given/When/Then 描述，验证方式必须包含测试框架（XCTest/XCUITest/手动）。
> **AC 编号体系**：AC-F1.12-1 ~ AC-F1.12-8（独立于 F1 主规范和其他 F1.x 的 AC）。

### AC-F1.12-1：点击文本区域进入编辑模式

- **Given** 主窗口已打开，用户选中一条文本类型（`.text`）剪贴项，详情面板展示该条目内容
- **When** 用户点击详情面板中的文本内容区域
- **Then** 只读 `Text` 视图切换为可编辑 `TextEditor` 视图，光标出现在点击位置，用户可输入文本
- **验证方式**：XCUITest

### AC-F1.12-2：编辑文本内容实时自动保存到数据库

- **Given** 用户已在详情面板中进入文本类型条目的编辑模式
- **When** 用户修改文本内容（输入或删除字符）
- **Then** 防抖延迟后，修改后的内容自动保存到数据库（EncryptedStore）；重新加载该条目后，内容为编辑后的最新版本
- **验证方式**：XCTest + XCUITest

### AC-F1.12-3：Cmd+Z 撤销编辑

- **Given** 用户已在详情面板中进入文本类型条目的编辑模式，并已输入若干字符
- **When** 用户按下 Cmd+Z
- **Then** 最近一次编辑操作被撤销，文本内容恢复到上一个状态；撤销操作触发自动保存
- **验证方式**：XCUITest

### AC-F1.12-4：切换到其他条目时自动保存

- **Given** 用户已在详情面板中编辑某条文本类型条目，且内容已修改
- **When** 用户在历史列表中点击另一条剪贴项
- **Then** 当前编辑的条目先保存到数据库，然后详情面板切换展示新选中的条目；重新加载原条目后，内容为编辑后的版本
- **验证方式**：XCUITest

### AC-F1.12-5：编辑保存后同步到系统剪贴板

- **Given** 用户已在详情面板中编辑某条文本类型条目，且自动保存已完成
- **When** 检查系统剪贴板（NSPasteboard.general）内容
- **Then** 系统剪贴板中的文本内容与编辑后的最新内容一致
- **验证方式**：XCTest

### AC-F1.12-6：文件路径类型可编辑

- **Given** 主窗口已打开，用户选中一条文件路径类型（`.filePath`）剪贴项
- **When** 用户点击详情面板中的路径文本区域，修改路径文本
- **Then** 路径文本进入编辑模式，修改后的路径文本实时自动保存到数据库
- **验证方式**：XCUITest

### AC-F1.12-7：图片类型显示不可编辑提示

- **Given** 主窗口已打开，用户选中一条图片类型（`.image`）剪贴项
- **When** 详情面板展示该图片类型条目内容
- **Then** 图片内容区域下方显示提示文本「图片内容不支持编辑」，图片内容不可点击进入编辑模式
- **验证方式**：XCUITest

### AC-F1.12-8：编辑后 AI 处理按钮仍可正常使用

- **Given** 用户已在详情面板中编辑某条文本类型条目，且自动保存已完成
- **When** 用户点击 AI 处理按钮（如智能总结）
- **Then** AI 处理按钮正常触发，处理结果基于编辑后的最新内容
- **验证方式**：XCUITest

## 9. Out of Scope（明确不做）

### 9.1 不重新触发自动分类

- 编辑后的内容不重新触发自动分类。
- ContentType 保持编辑前的值不变。
- 后续迭代再考虑编辑后自动重新分类。

### 9.2 不实现富文本编辑

- 编辑模式仅支持纯文本编辑，不支持富文本格式（加粗、斜体、链接等）。
- 不支持 Markdown 语法高亮和实时预览。
- 后续迭代再考虑富文本/Markdown 编辑支持。

### 9.3 不实现图片编辑

- 图片类型不支持任何编辑操作（裁剪、标注、旋转等）。
- 仅显示「图片内容不支持编辑」提示。
- 后续迭代再考虑图片标注或编辑功能。

### 9.4 不实现协同编辑

- 不支持多窗口同时编辑同一条目。
- 不支持多设备同步编辑。
- 不实现编辑冲突检测和解决。

### 9.5 不实现编辑历史版本

- 不保存编辑前的历史版本。
- 仅支持 Cmd+Z 撤销（在当前编辑会话内有效）。
- 关闭编辑会话后不可恢复原始内容。
- 后续迭代再考虑版本历史功能。

### 9.6 不修改剪贴板捕获逻辑

- PasteboardWatcher 的监听、去重、分类逻辑保持不变。
- 编辑后的内容不会触发 PasteboardWatcher 重新捕获。
- 编辑操作不写入新的 ClipItem。

### 9.7 不修改 AI 处理逻辑

- AI 处理的调用方式、参数、返回格式保持不变。
- 仅输入内容变为编辑后的最新内容，处理逻辑本身不变。

## 10. Terminology（术语）

| 术语 | 定义 |
|------|------|
| 详情面板 | 主窗口右侧展示选中剪贴项详细内容的区域，包含内容展示/编辑、元信息、AI 处理按钮和结果展示 |
| 只读模式 | 详情面板中文本内容的默认展示状态，使用 `Text` 视图，不支持输入 |
| 编辑模式 | 详情面板中文本内容的可编辑状态，使用 `TextEditor` 视图，出现光标可输入 |
| 自动保存 | 编辑模式下内容变化后自动保存到数据库的机制，无需用户手动触发保存 |
| 防抖 | 内容变化后延迟指定时间再触发保存的策略，避免高频写入 |
| 系统剪贴板同步 | 编辑保存后将最新内容写入 NSPasteboard.general 的操作 |
| 文本类型 | ClipContent.text(String)，包含纯文本内容的剪贴项类型 |
| 文件路径类型 | ClipContent.filePath([URL])，包含文件路径列表的剪贴项类型 |
| 图片类型 | ClipContent.image(Data)，包含图片二进制数据的剪贴项类型 |
| 编辑会话 | 从用户点击进入编辑模式到切换到其他条目或退出编辑的时间段 |
| 撤销 | 编辑会话内通过 Cmd+Z 恢复到上一个编辑状态的操作 |

## 11. Decision Freedom（实现自由度）

### 11.1 允许的实现自由度

- **编辑模式切换的实现方式**：可通过条件渲染（if/else 切换 Text/TextEditor）、焦点管理（@FocusState）或其他 SwiftUI 机制实现，只要满足「点击进入编辑模式、出现光标」约束。
- **防抖延迟时间**：自动保存的防抖延迟时间由设计阶段确定（建议 300ms~1000ms），本需求只约束「内容变化后自动保存」。
- **自动保存的实现方式**：可通过 Combine 的 debounce、Task + try await Task.sleep、Timer 或其他机制实现防抖，只要满足「延迟保存、不阻塞 UI」约束。
- **系统剪贴板同步的时机**：可在自动保存成功后立即同步，或在切换条目时统一同步，只要满足「保存后同步」约束。
- **文件路径编辑的展示格式**：多个文件路径的展示格式（换行分隔、逗号分隔等）由设计阶段确定，本需求只约束「路径文本可编辑」。
- **不可编辑提示的视觉风格**：提示文本的字体、颜色、位置由设计阶段确定，本需求只约束「显示提示文本」和「使用次要文字颜色」。
- **EncryptedStore update 方法的接口设计**：update 方法的签名、参数、返回值由设计阶段确定，本需求只约束「支持更新已存储的 ClipItem」。

### 11.2 禁止的实现方式

- **禁止使用私有 API**：所有实现必须使用公开 API，满足 App Store 合规。
- **禁止绕过沙盒**：所有实现必须在 App Sandbox 内完成。
- **禁止在日志中输出编辑内容原文**：所有日志仅记录元数据（如「已保存编辑，内容长度 256」），不记录编辑内容原文。
- **禁止使用固定 sleep 等待自动保存**：自动保存必须使用明确的防抖机制（如 Combine debounce），不用固定 sleep 掩盖竞态。
- **禁止编辑触发重新分类**：编辑后的内容不触发自动分类，ContentType 保持不变。
- **禁止编辑触发新的剪贴板捕获**：编辑操作不写入新的 ClipItem，不触发 PasteboardWatcher。
- **禁止图片类型进入编辑模式**：图片类型仅显示提示，不提供任何编辑能力。
- **禁止删除现有 save 方法**：EncryptedStore 现有的 save 方法保持不变，新增 update 方法。
- **禁止修改现有测试用例的辅助功能标识符**：F1.1~F1.11 已有的辅助功能标识符保持不变。

## 12. Future Considerations（未来扩展）

### 12.1 编辑后自动重新分类

- 当前编辑后不重新分类，未来可扩展：编辑保存后自动触发分类，更新 ContentType。
- 需考虑性能：每次编辑都触发嵌入模型推理可能过重，可延迟到编辑会话结束后批量处理。

### 12.2 富文本/Markdown 编辑

- 当前仅支持纯文本编辑，未来可扩展 Markdown 语法高亮和实时预览。
- 需考虑数据模型：ClipContent.text 目前存储纯文本，Markdown 格式需要额外的格式信息存储。

### 12.3 图片标注

- 当前图片类型仅显示不可编辑提示，未来可扩展图片标注功能（箭头、文本标注、马赛克）。
- 需考虑存储：标注数据需额外的数据结构存储，与原始图片数据分离。

### 12.4 编辑历史版本

- 当前仅支持 Cmd+Z 撤销（编辑会话内有效），未来可扩展版本历史。
- 版本历史可展示每次编辑的时间点和内容差异，支持恢复到任意历史版本。
- 需考虑存储：版本历史需要额外的数据库表存储。

### 12.5 文件路径验证

- 当前文件路径编辑仅修改路径文本字符串，不验证路径是否存在，未来可扩展路径验证。
- 可实时检查路径是否有效（文件/目录是否存在），无效路径显示警告。
- 需考虑性能：实时文件系统检查可能影响编辑体验。

### 12.6 批量编辑

- 当前仅支持单条目编辑，未来可扩展批量编辑（如批量替换关键词、批量追加文本）。
- 需考虑 UX：批量编辑需要选择多个条目的交互设计。
