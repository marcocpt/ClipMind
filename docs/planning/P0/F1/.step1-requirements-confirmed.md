# F1.14 上游需求摘要复用确认

> 最后更新：2026-07-28 | 版本：v1.0

## 1. 来源与恢复结论

- 上游摘要：`docs/planning/P0/F1/.feature-step0-requirements-summary.md`。
- 摘要正文描述“用户自定义标签”，但标题和功能编号仍写为 F1.13。
- 当前用户请求、工作分支 `feature/F1.14-user-tags` 以及已提交的 F1.13“来源过滤”规格共同证明，本功能编号应恢复为 F1.14。
- F1.14 四篇现有文档均未提交，Requirements 尚未通过审查和用户确认；下游三篇在 Requirements Gate 前均视为 stale。

## 2. 已复用需求事实

- 用户可在主窗口、菜单栏弹窗和快捷粘贴面板的条目上搜索、多选、创建、添加或移除标签。
- 自动分类标签与用户自定义标签统一展示，每条剪贴项最多 5 个标签。
- 主窗口支持标签过滤，多个标签采用交集语义，并与现有搜索及来源筛选组合。
- 设置页提供标签管理。
- 老用户数据需完成幂等迁移，标签元数据与关联关系必须加密持久化。
- 本功能不包含分组、层级、自由色值、排序、导入导出、AI 推荐或标签快捷键。

## 3. 用户确认的冲突处置

决策 F1.14-D01：

- 自动分类标签可在单条剪贴项上移除和恢复。
- 设置页仅允许全局重命名或删除用户自定义标签。
- 自动分类标签在设置页可见但只读，不能全局重命名或删除。

此决策避免自动分类标签被全局删除后，由迁移或后续分类重新创建而造成用户操作失效。

## 4. Requirements 写作边界

- 保留现有自动分类标签的用户可见名称与颜色，避免升级造成无关视觉变化。
- 标签名称属于用户输入，不得写入日志；名称、颜色和关联关系均须加密存储。
- Requirements 只写业务行为；现有代码类型、数据库表、模块名和组件名留给 Design/Implementation Plan。
- Requirements 修订后必须完成三视角审查并取得用户确认，才能进入 Design。
