## 1. 测试策略与覆盖口径

### 1.1 基线与边界

- 本表以已确认的 Requirements v1.2、Design v2.2 和 Visual Prototype v2.3 为唯一功能基线。
- F1.14 新增标签目录、条目关联、自动标签处置、标签规则、组合筛选、设置管理、迁移和安全诊断测试；不把既有 `ContentType` 彩色文本直接视为用户标签能力。
- F1.13 来源筛选基线当前缺少 `SourceFilterSelection` 等符号，构建退出 65。该缺口不改变用例定义，但阻止 F1.14 完整实现验收；所有依赖来源筛选的用例必须在基线恢复后执行。
- 本轮没有获批的延后项，因此不得使用 `⏸️ DEFERRED` 掩盖缺口。

### 1.2 测试层级

| 层级 | 主要职责 | 证据 |
|------|---------|------|
| XCTest 单元 | 标签规则、名称校验、上限、来源资格、排序和状态转换 | 精确值、错误类别、前后状态 |
| XCTest 集成 | 加密持久化、原子变更、迁移、组合筛选、日志和性能 | 数据库原始字节、解密回读、条目标识集合、性能指标 |
| XCUITest | 三个真实入口、标签菜单、设置页、空态、确认与失败回滚 | 可访问性标识、可见文本、角色、状态和条目结果 |
| CI / 静态审查 | 双架构、macOS 13+、entitlement、公开 API 和依赖边界 | 构建测试结果、产物 entitlement、依赖差异 |
| 手动验证 | VoiceOver、Accessibility Inspector、Instruments 和发布产物复核 | 截图、检查记录、内存曲线和产物清单 |

### 1.3 覆盖状态定义

| 状态 | 判定标准 |
|------|---------|
| ✅ COVERED | 当前仓库存在真实测试，完整执行该用例的 Given/When/Then 并断言所列证据 |
| 🟡 PARTIAL | 当前测试只覆盖前置基础能力、单一入口或部分断言，不能替代 F1.14 完整用例 |
| ❌ MISSING | 当前没有对应生产能力或测试，或现有测试无法观察该用例的核心结果 |
| ⏸️ DEFERRED | 仅在用户明确批准延后，并记录负责人和触发条件后使用；本表当前为 0 |

### 1.4 当前代码与测试审计

| 已有证据 | 可复用边界 | 不能证明 |
|---------|-----------|---------|
| `TypeTagView.swift`、`PopoverUITests.swift`、`SampleDataUITests.swift` | `CODE/LINK/ERROR` 等既有系统标签文本和部分入口显示 | 用户标签、菜单交互、移除恢复、三个入口一致性 |
| `SearchUITests.swift`、`SourceFilterTests.swift` | 既有搜索与来源筛选的基础行为 | 标签条件、多个标签交集、清除标签后保留其他条件 |
| `EncryptionTests.swift`、`EncryptedStoreTests.swift` | 剪贴项内容的加密落盘和回读基础设施 | 标签名称、颜色、来源、关联和处置状态的加密 |
| `AutoSaveAC22LogSanitizationTests.swift`、`LoggerTests.swift` | 非标签路径的日志分类和部分静态脱敏规则 | 标签成功与失败日志中的哨兵文本防泄漏 |
| `ClipItemModelTests.swift` | 11 种 `ContentType` 和 Codable 基线 | 标签领域身份、用户标签或条目关联 |

**审计结论**：当前 AC 级覆盖为 0 个 COVERED、6 个 PARTIAL、18 个 MISSING、0 个 DEFERRED。仓库中未发现 F1.14 标签领域模型、标签关联、设置标签管理、标签迁移或对应测试。

### 1.5 性能基准合同

- 基准任务使用 macOS 15、arm64、Release 配置、1000 条固定剪贴项夹具和固定标签组合。
- 每项先预热 1 次，再测量 10 次并记录 p95；同时保存 runner image、CPU、内存和架构元数据。runner class 变化时必须先重建基线，不能直接比较。
- 菜单打开与创建标签不超过 200ms；菜单搜索不超过 100ms；勾选或取消不超过 50ms；主窗口标签过滤不超过 200ms。
- 1000 条迁移不超过 3s；相对无迁移场景，首个可交互界面的额外延迟不超过 200ms。
- x86_64 只承担兼容构建和功能测试，不与 arm64 性能阈值混算。

## 5. 执行顺序与 Gate

1. 先恢复 F1.13 来源筛选基线编译；该修复属于独立上游任务。
2. 以 DOM、MIG、SEC 用例建立标签领域、原子持久化和迁移安全网。
3. 实现三个入口与设置页时，按 UI-ENTRY、UI-MENU、SET 用例做 TDD。
4. 组合筛选接入后执行 FLT 与 REG，确认历史和搜索消费同一 resultId 集合。
5. 功能用例通过后运行 PERF、STAB、A11Y、COMP；性能与合规证据必须绑定候选 SHA。
6. Test Matrix 独立 Review A/B/C 与用户确认前，本表仍是草稿，不得作为 Implementation 完成证据。
