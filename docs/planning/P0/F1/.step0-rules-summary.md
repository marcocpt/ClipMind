# F1.14 规格文档规则摘要

> 最后更新：2026-07-28 | 版本：v1.0

## 1. 文档层级

- Requirements：描述产品合同与可观察行为，不包含代码符号、框架 API、文件路径或实现技术。
- Design：描述模块职责、边界、数据流、状态与关键决策，不复制 Requirements，不写实现代码。
- Visual：覆盖所有用户可见状态、错误与边界，头部显示更新时间和版本。
- Test Matrix：覆盖每条 FR/AC、失败路径、兼容性和真实 UI 证据，并诚实标注已有覆盖状态。

## 2. 顺序与文件

按以下顺序逐篇完成、审查、确认和提交：

1. `F1.14_用户自定义标签_需求文档.md`
2. `F1.14_用户自定义标签_设计文档.md`
3. `F1.14_用户自定义标签_视觉原型.html`
4. `F1.14_用户自定义标签_测试用例表.md`

存放目录：`docs/planning/P0/F1/`。

## 3. 格式

- Markdown 标题后第一行使用 `> 最后更新：YYYY-MM-DD | 版本：vX.Y`，文末保留版本记录。
- Test Matrix 的版本头同时注明所基于的 Requirements/Design 版本。
- 中文标点，英文术语保持原文。
- 相对链接，不写绝对路径。
- Mermaid 兼容 9.1.2，节点文本不使用中文标点或特殊符号。

## 4. 同步与审查

- 目标、范围、流程、接口或 AC 变化时同步下游 Test Matrix。
- UI 行为变化时同步 Visual。
- 技术架构、数据模型、迁移或异常处理变化时同步 Design。
- 每篇执行覆盖与范围、一致与正确、可验证与可观测三视角审查。
- 关键文档变化追加 `historys/YYYY-MM-DD-修改摘要.md`。
