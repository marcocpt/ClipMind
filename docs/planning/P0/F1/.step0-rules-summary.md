# F1.10 步骤 0 规则与参考摘要

> 本文件由 dd-writing-specs 步骤 0 写入，用于记录项目规则提取与既有规格文档参考，供后续步骤 1~5 复用。结束后由步骤 5.7 清理。

## 1. 项目 docs.md 10 项规则提取

**规则来源**：`.trae/rules/docs.md`（仓库根目录）+ `AGENTS.md`（项目主入口）+ `docs/CODING_STANDARDS.md`（编码规范）。

### 1.1 文档目录结构

- `planning/P{n}/F{m}/`：按优先级与功能编号组织。
- `planning/P{n}/F{m}/historys/`：每次涉及 docs/、功能设计或关键架构决策的 commit 必须写日志，命名 `YYYY-MM-DD-修改摘要.md`，内容：改了什么、为什么、影响哪些部分。
- F1.10 文档目录：`docs/planning/P0/F1/`（沿用 F1 系列约定，与 F1.9 同级）。
- F1.10 history 日志：`docs/planning/P0/F1/historys/2026-07-25-F1.10-快捷键默认值修改.md`。

### 1.2 文档命名规则（4 篇套件）

参考 F1.9 既有命名（已落地）：

| 文档类型 | 文件名 | 是否必需 |
|---------|--------|---------|
| 需求文档 | `F1.10_快捷键默认值修改_需求文档.md` | 必须 |
| 设计文档 | `F1.10_快捷键默认值修改_设计文档.md` | 必须 |
| 视觉原型 | `F1.10_快捷键默认值修改_视觉原型.html` | 涉及 UI 时（F1.10 涉及设置页 HotkeyRecorder 显示，需要） |
| 测试用例表 | `F1.10_快捷键默认值修改_测试用例表.md` | 必须 |

> 注：docs.md 字面写「设计规范」，但 dd-writing-specs 已分层为「需求文档 + 设计文档」，F1.9 也按 4 篇落地。本特性沿用 4 篇约定。

### 1.3 编写顺序

需求文档 → 设计文档 → 视觉原型（涉及 UI 时）→ 测试用例表。每篇逐份完成（写 → 3 子代理审 → 合并 → 一次一问确认 → 提交）。

### 1.4 文档头部格式

- Markdown：标题后第一行 `> 最后更新：YYYY-MM-DD | 版本：vX.Y`，每次修改同步更新。
- HTML：页面头部显示最后更新时间与版本信息。
- 文档末尾添加版本记录列表（表格形式）。

### 1.5 标点符号规则

- 中文标点（，。！？：；）。
- 英文术语保持原文（如 `HotkeyFormatter`、`AppSettings`、`@AppStorage` 等代码标识符原文保留）。
- mermaid 图内不使用中文标点、符号。

### 1.6 mermaid 规则

- 用于流程图、状态图、类图、序列图。
- 格式兼容 9.1.2。
- 不使用中文标点、符号。

### 1.7 同步更新规则

- 修改设计规范/需求文档中的目标、范围、流程、接口、验收标准时，必须同步更新测试用例表。
- 涉及 UI 行为变化时，必须同步更新视觉原型。
- 每次关键变更必须追加版本记录和 history 日志。

### 1.8 链接路径规则

- 链接用相对路径，不硬编码绝对路径。

### 1.9 编码规范参考

`docs/CODING_STANDARDS.md`：
- Swift 5.7+ / macOS 13+。
- Allman 大括号风格，4 空格缩进。
- 公共 API 必须有文档注释。
- 使用 `LogCategory` 记录日志，禁止 `print()`。
- 错误日志需要上下文 metadata，日志不得输出敏感信息或用户输入。
- UI 状态更新必须在主线程或 `@MainActor` 边界内。
- 避免魔术数字和魔术字符串；配置键、UserDefaults 键、通知名使用命名常量。
- Mock 只模拟外部依赖，不 mock 被测对象本身。
- 测试规范：行为变化必须有测试，异步测试不使用 sleep，测试验证行为不验证实现。

### 1.10 App Store 合规要求（AGENTS.md 第 10 节）

- 主 Scheme `ClipMind` 是 App Store 上架构建目标，必须保持完全合规。
- `ClipMind-Dev` 是开发验证用 Scheme，仅用于本地验证。
- F1.10 涉及全局快捷键，但仅修改默认值和扩展解析器，不改变注册流程，主 Scheme `ClipMind` 仍完全合规。
- 暂存于 `ClipMind-Dev` 的特性需在对应设计规范/实施草案中标注「合规待定」状态。

## 3. 既有规格文档可复用写作模式（参考 F1.9）

### 3.1 F1.9 需求文档（`F1.9_快捷粘贴面板_需求文档.md` v1.1）

**章节结构**（12 章，符合 dd-write-requirements 默认）：
1. Background（背景）
2. Problem Statement（问题定义）
3. Goals（目标，含用户/业务/成功标准三子节）
4. Scope（范围，含必须做/必须不做）
5. Functional Requirements（FR-001 起）
6. Non-functional Requirements（NFR-001 起，可测量）
7. Constraints（约束，含业务/兼容/合规三子节）
8. Acceptance Criteria（AC，Given/When/Then + 验证方式）
9. Out of Scope（明确不做）
10. Terminology（术语表）
11. Decision Freedom（实现自由度，允许 + 禁止双向）
12. Future Considerations（未来扩展）

**AC 写法**：编号 `AC-F1.9-1 ~ AC-F1.9-12`，Given/When/Then 三段式 + 验证方式（XCTest/XCUITest/手动）。
**版本记录**：表格形式，记录版本号、日期、变更说明。

### 3.2 F1.9 设计文档（`F1.9_快捷粘贴面板_设计文档.md` v1.1）

**章节结构**（10 章，符合 dd-write-design 默认）：
1. 文档定位（含设计目标、设计约束）
2. 模块划分（新增/修改/复用三层 + 模块依赖图 mermaid）
3. 职责边界（每个模块"负责/不负责" + 职责边界无冲突验证表）
4. 数据流（mermaid 序列图，按场景拆分）
5. 状态变化（mermaid 状态机 + 状态说明表）
6. 协作关系（按模块对展开）
7. 关键设计决策（"为什么 X" 形式，每项含决策 + 理由）
8. 非功能约束落地（NFR 到落地方式映射表）
9. 与 Requirements 的映射（FR 到模块映射表 + NFR 落地映射）
10. 风险和待确认问题（技术风险 + 合规风险 + 待确认问题）

**P0 铁律**：设计文档不包含具体代码（无类定义/方法签名/字段类型/枚举值/文件路径）、不含 AC、不含测试策略（已迁移到测试用例表）、不含分阶段设计（属于实现规划）。

### 3.3 F1.9 测试用例表（`F1.9_快捷粘贴面板_测试用例表.md` v1.0）

**章节结构**（7 节）：
1. 概述（覆盖范围 + 覆盖状态说明 + 测试框架 + 测试组织结构规划）
2. 测试用例总表（功能验收 + 非功能验证两表）
3. 测试用例详情（按 AC 编号展开，每个 TC 含前置/步骤/预期/状态/备注）
4. 测试数据集准备
5. 测试执行计划（按 Phase 拆分 + 执行顺序 + CI 集成）
6. 覆盖度统计（AC 覆盖度 + NFR 覆盖度 + 总体覆盖度）
7. 版本记录

**用例编号**：`TC-F1.9-{AC号}-{序号}`（功能验收）+ `TC-F1.9-{类型}-{序号}`（非功能，类型如 P 性能/S 稳定/SEC 安全/C 兼容/A 可访问/COMP 合规）。
**覆盖状态**：✅ COVERED / 🟡 PARTIAL / ❌ MISSING / ⏸️ DEFERRED。
**文档头部**：`> 最后更新：YYYY-MM-DD | 版本：vX.Y（基于需求文档 vA.B + 设计文档 vC.D）`。

### 3.4 F1.9 视觉原型 HTML（`F1.9_快捷粘贴面板_视觉原型.html` v1.0）

**结构特征**：
- `<!DOCTYPE html>` + `<html lang="zh-CN">` + HTML 注释（版本/最后更新/关联文档/覆盖 AC/说明）。
- macOS 原生浅色风格（`-apple-system` 字体、`#ececec` 背景、`#ffffff` 卡片、`#d1d1d1` 边框、`0 1px 3px rgba(0,0,0,0.06)` 阴影）。
- 顶部标题区 `.page-header`（h1 + meta span）。
- 场景容器 `.scene`，每个场景独立卡片。
- 静态视觉示意，不包含真实交互逻辑。
- 浏览器直接打开。

## 4. F1.10 关键设计要点（来自上游需求摘要）

- **HotkeyFormatter 扩展**：`keyName`/`keyCode` 映射增加 `49 ↔ "space"`；`display` 方法 `space → "Space"` 大写显示。
- **三处默认值同步**：`AppSettings.hotkey`、`GeneralSettingsView.@AppStorage`、`HotkeyRecorder` 重置按钮。
- **老用户迁移**：`AppSettings.migrateLegacyHotkey()` 方法，仅当 `hotkey == "cmd+shift+v"` 时迁移为 `cmd+shift+space`，自定义值保留。
- **测试常量化**：新增 `ClipMindTests/TestSupport/TestHotkeys.swift`，包含 `default`/`legacyDefault`/`arbitrary` 三个常量。
- **测试策略**：1 改 + 8 新增 + 5 fixture 改用 `TestHotkeys.arbitrary`；保留 `cmd+shift+v` 解析器测试作为回归保护（AC-F1.10-10）。
- **AC 共 10 条**（含 1 条回归保护 AC-F1.10-10）。
- **单 Phase 一次性完成**（用户已确认阶段划分）。
- **App Store 合规**：仅修改默认值和扩展解析器，不改变注册流程，主 Scheme `ClipMind` 仍完全合规。
